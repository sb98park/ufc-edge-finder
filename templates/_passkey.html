{# PASSKEY SIGN-IN, spoken to GoTrue directly. The rest of this site talks to Supabase over raw REST and carries no SDK, so this does the same rather than pulling in @supabase/supabase-js for two requests. The contract below was read out of auth-js rather than guessed: POST /auth/v1/passkeys/authentication/options anon key, no session -> { challenge_id, options: { challenge, timeout, rpId, userVerification }, expires_at } navigator.credentials.get({ publicKey: options }) POST /auth/v1/passkeys/authentication/verify { challenge_id, credential } -> a normal Supabase session Registration is the same shape at /passkeys/registration/*, except those two DO need the user's own access token -- which is why enrolment is offered right after an email sign-in, while we still hold one. DISCOVERABLE CREDENTIALS. The options come back with no allowCredentials list, so the authenticator shows its own account picker and we never ask for an email first. That is the whole point: tap, Face ID, in. #}
